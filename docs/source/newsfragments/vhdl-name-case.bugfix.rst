Fixed looking up a VHDL object by a name that differs from the source only in the case of basic identifiers (e.g. ``dut.DATA_IN`` for ``data_in``). Depending on the simulator and on whether the design had already been iterated, this gave a separate handle, a handle of the wrong type, or no object at all. An extended identifier that is the name being looked up is now only found in exactly its case (see :ref:`writing_tbs_accessing_underscore_identifiers` for objects below extended identifiers that differ only in case). NVC now also finds an extended identifier with a backslash in it by its source form (e.g. ``\a\\b\``).
